# J9 · Prêt pour le live

Objectif : une soirée blanche sans intervention, des paquets installables, un guide pour les opérateurs.

---

### J9-01 · Tests d'endurance

- **Modèle :** Sonnet 5.5 · effort `high`
- **Dépend de :** J8-01, J7 terminé
- **Skills :** `live-safety`, `render-performance`

**À faire**

- Mode `--soak <heures>` : démo en boucle, actions aléatoires réalistes (GO, passations, drops forcés), export CSV
  (mémoire CPU/GPU, temps d'image, entités, compteurs audio).
- Simulation logique accélérée de 6 h en test automatisé (sans rendu).

**Critères d'acceptation**

- [ ] 6 h réelles : mémoire plate après 15 min, aucune image > 50 ms hors passation (courbes dans la PR).

---

### J9-02 · Pertes de sources et replis

- **Modèle :** Sonnet 5.5 · effort `high`
- **Dépend de :** J3-03, J2-05
- **Skills :** `live-safety`, `midi-control`, `realtime-audio`

**À faire**

- Injecteurs de pannes (feature `fault-injection`) : perte audio, perte clock, contrôleur débranché, look corrompu,
  panique d'un système. Vérifier chaque repli du skill `live-safety`.

**Critères d'acceptation**

- [ ] Chaque panne a un test automatisé ou un protocole manuel documenté, et le show continue.

---

### J9-03 · Paquets d'installation

- **Modèle :** Sonnet 5.5 · effort `medium`
- **Dépend de :** J0-01
- **Skills :** `workflow-conventions`

**À faire**

- `cargo-dist` (ou `cargo-packager`) : installeur Windows, `.dmg` macOS (universel ou arm64), AppImage/tar Linux ;
  assets embarqués à côté du binaire ; workflow de release sur tag `v*`.
- Notes sur la signature (macOS notarisation, Windows SmartScreen) sans secret dans le dépôt.

**Critères d'acceptation**

- [ ] Un tag de test produit les trois paquets en CI ; installation testée sur au moins une machine par OS.

### J9-04 · Guide de l'opérateur

- **Modèle :** Sonnet 5.5 · effort `medium`
- **Dépend de :** J8 terminé
- **Skills :** `midi-control`, `live-safety`

**À faire**

- `docs/guide-operateur.md` (FR) : installation, brancher son et MIDI (loopMIDI sous Windows, bus IAC sous macOS,
  MIDI Clock depuis Traktor/Rekordbox/Serato), préparer une soirée, jouer, en cas de pépin.

**Critères d'acceptation**

- [ ] Relu par le propriétaire du dépôt ; une personne qui ne connaît pas l'app prépare et joue un set avec.

### J9-05 · Campagne de performance sur le matériel cible

- **Modèle :** Sonnet 5.5 · effort `high`
- **Dépend de :** J9-01
- **Skills :** `render-performance`

**À faire**

- Mesures sur la machine de soirée (fournie par le propriétaire du dépôt) en 1080p et 4K ; profilage (Tracy via
  `bevy/trace_tracy`) des 5 postes les plus coûteux ; corrections ciblées.

**Critères d'acceptation**

- [ ] 1080p 60 i/s stables au niveau 5 sur la machine cible (rapport dans `docs/perf/`).

---

### J9-06 · Mise à jour automatique

- **Modèle :** Sonnet 5.5 · effort `medium`
- **Dépend de :** J9-03
- **Skills :** `live-safety`, `bevy-patterns`

**À faire**

- Vérification au démarrage des releases GitHub (`cargo-packager-updater`), sur un thread à part, sans jamais gêner le
  show ; bandeau et bouton d'installation dans la vue de préparation de l'opérateur, jamais en Live.
- Workflow de release : paquets signés (clé dans le secret `UPDATER_PRIVATE_KEY`), `latest.json` publié avec la release.
- Documenter la mise en place des clés (`docs/distribution.md`).

**Critères d'acceptation**

- [ ] Une release publie `latest.json` et les signatures ; l'application installée voit la version suivante et s'y met à jour sous Windows.
- [ ] Hors réseau ou avec un manifeste invalide, l'application démarre normalement et journalise un avertissement.
- [ ] Aucune installation n'est possible en vue Live.
