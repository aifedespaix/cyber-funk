# J1 · Audio

Objectif : entendre les démos, écouter le micro, et produire en continu des `AudioFeatures` identiques à ce que
Sillage détecte. Démo de fin : vumètres, BPM et sections en direct dans la fenêtre opérateur.

Sources Sillage : `apps/main/src/components/sillage/` (dépôt `aifedespaix/aifedespaix.com`).

---

### J1-01 · Données de référence extraites de Sillage (golden)

- **Modèle :** Opus 5.5 · effort `high`
- **Dépend de :** J0-03 (pistes CC0)
- **Dossier :** `tools/sillage-golden/` (script Bun/TypeScript)
- **Skills :** `sillage-porting`, `realtime-audio`
- **Sources :** `engine/beat.ts`, `engine/sections.ts`, `engine/audio.ts` (paramètres de l'`AnalyserNode`, `BandGain`),
  `engine/show/build.ts`

**À faire**

- Script Bun qui décode les 4 pistes CC0 en PCM mono 48 kHz, **émule l'`AnalyserNode` Web Audio** (fenêtre de
  Blackman, `smoothingTimeConstant`, conversion dB → octets avec `minDecibels`/`maxDecibels`, même `fftSize` que
  Sillage) en appelant les **fichiers TS d'origine** de `beat.ts` et `sections.ts` (copiés tels quels ou importés), à
  pas fixe équivalent à 60 i/s.
- Sortie JSON par piste dans `crates/cf-analysis/tests/golden/` : horodatages des kicks, BPM au fil du temps, sections
  et intensité échantillonnées, détections de montée (`build.ts`).
- README du dossier : comment régénérer, version de Sillage (hash de commit) utilisée.

**Critères d'acceptation**

- [ ] `bun run tools/sillage-golden/index.ts` régénère les fichiers à l'identique (déterministe).
- [ ] Les BPM détectés sont plausibles pour chaque piste (indiquer le BPM réel connu dans la PR).

### J1-02 · Lecture des pistes de démo

- **Modèle :** Opus 5.5 · effort `high`
- **Dépend de :** J0-01, J0-03
- **Crate :** `cf-audio`
- **Skills :** `realtime-audio`, `rust-conventions`
- **Sources :** `engine/audio.ts` (playlist, modes `random`/`sequence`/`loop`, volume, sourdine), `tracks.ts`

**À faire**

- Décodage `symphonia` sur un thread dédié vers un `rtrb`, sortie `cpal` (callback sans allocation ni verrou).
- Playlist depuis `assets/music/` + `assets/music/local/` ; modes de lecture de Sillage ; volume et sourdine qui ne
  touchent **pas** le signal envoyé à l'analyse.
- Position de lecture exacte (compteur d'échantillons) exposée ; le signal joué est aussi poussé vers l'analyse.
- API : `Player::play/pause/next/prev/seek/set_volume`, état observable (piste, position, durée).
- Exemple `examples/play.rs`.

**Critères d'acceptation**

- [ ] Lecture sans craquement sur les trois OS (décrire le test), passage à la piste suivante sans trou audible.
- [ ] Revue du callback : aucune allocation, aucun verrou (le justifier ligne par ligne dans la PR).
- [ ] Compteur de sous-alimentation (underrun) exposé et à 0 sur une lecture complète.

### J1-03 · Capture d'entrée et thread d'analyse

- **Modèle :** Opus 5.5 · effort `xhigh`
- **Dépend de :** J0-01
- **Crates :** `cf-audio`, `cf-analysis` (squelette `AudioFeatures`)
- **Skills :** `realtime-audio`, `rust-conventions`

**À faire**

- Énumération et choix du périphérique d'entrée (par nom), formats i16/u16/f32, mono-mix, rééchantillonnage vers 48 kHz
  si nécessaire (`rubato`).
- Callback → `rtrb` → **thread d'analyse à pas fixe** (512 échantillons à 48 kHz) → `triple_buffer<AudioFeatures>` +
  canal borné d'événements datés.
- Source commutable à chaud : micro/ligne ou lecteur de démo (J1-02), sans redémarrer le thread.
- Struct `AudioFeatures` définie selon le skill `realtime-audio` (champs non encore calculés à valeur neutre).
- Rebranchement : perte du périphérique détectée, reconnexion par nom, `live = false` en attendant.

**Critères d'acceptation**

- [ ] Test d'intégration sans matériel : source synthétique injectée → features publiées au bon rythme.
- [ ] Latence callback → publication mesurée et affichée en journal debug (< 15 ms visé).
- [ ] Débrancher/rebrancher une interface USB pendant l'exécution ne fait pas planter (décrire le test).

### J1-04 · Détecteur de kicks et tempo (portage de `beat.ts`)

- **Modèle :** Opus 5.5 · effort `high`
- **Dépend de :** J1-01, J1-03
- **Crate :** `cf-analysis`
- **Skills :** `sillage-porting`, `realtime-audio`
- **Sources :** `engine/beat.ts`, paramètres d'analyse de `engine/audio.ts`

**À faire**

- Module `analyser_emulation` : reproduit `getByteFrequencyData` (même fenêtre, lissage, échelle) avec `realfft`.
- Portage de `BeatDetector` à l'identique (bandes, flux, moyenne glissante, période réfractaire, médiane des
  intervalles repliée 70–180 BPM, oubli après silence), constantes reprises.
- Indépendance au pas de temps conservée (Sillage corrige par `dt`).
- Tests golden contre J1-01 avec les tolérances du skill `realtime-audio` ; tests synthétiques (clics à 120, 128,
  174 BPM ; silence ; bruit blanc).
- Bench `criterion` d'un pas d'analyse.

**Critères d'acceptation**

- [ ] Golden : ≥ 95 % des kicks à ±1 pas, BPM ±0,5 en régime établi, sur les 4 pistes.
- [ ] Bench : < 0,5 ms par pas en release.
- [ ] Aucune allocation par pas (vérifié par test avec un allocateur compteur, ex. `assert_no_alloc`).

**Critères d'acceptation**

- [ ] Golden : sections identiques hors ±1 s autour des changements, intensité à ±0,05.
- [ ] Micro simulé à -30 dB : les bandes retrouvent leur plage de fichier en < 20 s (comme Sillage).
